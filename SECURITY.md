## Reporting a Vulnerability

We take the security and integrity of this project seriously. If you discover a potential security vulnerability in the tooling, scripts, dependencies, or continuous integration workflows, please report it privately.

### Preferred Method: Private Vulnerability Reporting

Please submit vulnerability reports directly through GitHub's [Private Vulnerability Reporting](https://github.com/bdperkin/ecu-licensing-trademarks/security/advisories/new) system:

1. Navigate to the **[Security](https://github.com/bdperkin/ecu-licensing-trademarks/security)** tab of this repository.
2. Select **[Advisories](https://github.com/bdperkin/ecu-licensing-trademarks/security/advisories)** in the left sidebar.
3. Click **Report a vulnerability** to open a confidential advisory draft.
4. Fill in the vulnerability details, severity assessment, and reproduction steps.

### What to Include in Your Report

To help us investigate and resolve the issue quickly, please include:

- A clear description of the vulnerability and its potential impact.
- Step-by-step instructions or proof-of-concept (PoC) to reproduce the issue.
- Details regarding affected files, scripts, functions, or dependencies.
- Any suggested remediations or mitigations, if known.

---

## Response Process & SLA

1. **Acknowledgment**: We aim to acknowledge receipt of security reports within **48 hours**.
2. **Investigation & Triage**: We will assess the severity and impact, verifying the vulnerability in a private security advisory environment.
3. **Remediation**: Once verified, a security patch will be developed, reviewed, and tested.
4. **Coordinated Disclosure**: We will publish a patched release along with a CVE/GitHub Security Advisory crediting the reporter (unless anonymity is requested).
